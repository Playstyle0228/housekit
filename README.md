# HouseKit — 烏日新成屋實質成交單價與回檔走勢

以內政部實價登錄原始資料，自動產製烏日區新成屋實質成交單價的月／季走勢，
並拆分「烏日全區」「高鐵特區」「明道商圈」三個地理層級互相比較。

零第三方依賴（純 Python 標準庫），資料每月 1／11／21 日由 GitHub Actions 自動更新。

---

## 快速開始

```bash
python scripts/ingest.py --backfill    # 一次性回填 111S4 起所有季檔（約 1.8 GB 下載）
python scripts/aggregate.py            # 產製 docs/data.json
python -m http.server -d docs 8000     # 本機預覽 http://localhost:8000
```

日常更新只需（CI 也是跑這兩行，下載量約 14 MB）：

```bash
python scripts/ingest.py               # 只抓尚未收錄的旬檔
python scripts/aggregate.py
```

## 部署

GitHub Pages：repo Settings → Pages → Source 選 `main` 分支的 `/docs` 目錄。
`docs/index.html` 以相對路徑讀取同目錄的 `data.json`，無需後端。

## 資料來源

內政部不動產成交案件實際資訊資料供應系統（`plvr.land.moi.gov.tw`），
使用「不動產買賣（成屋）」A 檔。三種端點與實測結果：

| 端點 | 內容 | 實測大小 | 保留期 |
|---|---|---|---|
| `DownloadHistory?type=season&fileName=115S2` | 全國一季 zip（756 檔） | 94～170 MB | 101S1 起永久 |
| `DownloadHistory?type=history&fileName=20260821` | 全國一旬 zip | 13～19 MB | **僅最近 6 旬** |
| `Download?fileName=b_lvr_land_a.csv` | 單縣市當期一旬 CSV | 約 433 KB | 當期 |

檔名規則 `{縣市碼}_lvr_land_{類別}.csv`，`b` = 臺中市，
類別 `a` = 成屋買賣、`b` = 預售屋、`c` = 租賃。編碼 UTF-8 with BOM，
**CSV 第 2 列是英文欄名，必須跳過**。

季檔以**登記日期**而非交易日期切分（如 115S2 = 登記 115/3/11～6/10），
因此跨季合併必須以「編號」欄去重。

伺服器雖回應 `Accept-Ranges: bytes`，但實測帶 `Range` 仍回 200 與完整長度，
**無法對 zip 做部分讀取**，只能整份下載。

## 架構

```
scripts/fetch.py       下載層：期別清單解析、zip 取用、登記期間推算
scripts/clean.py       清洗層：實質單價、屋齡、遞延與特殊交易剔除
scripts/zones.py       分區定義：烏日全區／高鐵特區／明道商圈 門牌白名單
scripts/store.py       持久層：data/records.csv.gz + data/state.json
scripts/ingest.py      下載並清洗新來源，寫入持久層
scripts/aggregate.py   聚合成 docs/data.json（月頻＋季頻）
docs/index.html        前端，讀取同目錄 data.json
legacy/                原始 Apps Script 原型（資料為手填佔位值，僅存參考）
```

### 為什麼要有持久層

1. 旬檔只保留最近 6 旬，過期即無法取得，必須自行留存。
2. 季檔每份逾百 MB，CI 每次重下 1.8 GB 不現實；持久層讓 CI 只需下載新增旬檔。
3. 持久層保留台中市門牌（`addr`）而非僅存分區代碼，因此**調整 `zones.py`
   的商圈範圍只要重跑 `aggregate.py`，不必重跑回填**。

`data/records.csv.gz` 目前約 32 萬筆、6.9 MB，依（交易月, 編號）排序寫出，
使 git diff 穩定。

## 指標定義

**實質單價（萬元／坪）**

```
(總價元 − 車位總價元) ÷ ((建物移轉總面積 − 車位移轉總面積) × 0.3025) ÷ 10000
```

先自總價與面積扣除車位再換算坪單價，避免含車位案件壓低單價。

**新成屋**：屋齡 = 交易年月 − 建築完成年月 ≤ 5 年。
每個分區同時輸出 `new`（新成屋）與 `all`（全屋齡）兩組，前端可切換。

**代表值**：中位數。樣本少時較平均數穩健、不受少數高單價個案拉動；
另輸出 P25／P75 與樣本數 n。

前端「取值」可切換單期或 **3 期合併**。合併是把視窗內各期的*交易明細倒在一起*
後取中位數，而非對各期中位數再平均。低樣本分區（明道商圈每季僅 5～16 筆）的
單期中位數鋸齒劇烈，合併後才有可讀趨勢，且不會憑空造出資料點。
圖表一律以直線連接（`tension: 0`）—— 低樣本序列用曲線平滑會製造不存在的過衝。

**納入建物型態**：住宅大樓、華廈。排除透天厝、店面、廠辦等含大量土地價值、
單價不可比者。

## 三道正確性控制

### 1. 交屋遞延剔除

實價登錄當期揭露資料中含大量數年前簽約、近期才登記的案件。實測 115/08 旬檔
台中市 1,162 筆中，僅 517 筆是 115/06～08 成交，其餘 645 筆是 109～114 年成交。

備註欄「預售屋、或土地及建物分件登記案件」與申報遞延月數完全對應、零重疊：

```
有此備註   → 遞延 21～49 個月
無此備註   → 遞延 −2～7 個月
```

同時以備註關鍵字與登記遞延月數（上限 6 個月）雙重剔除，互為驗證。
以烏日區 115S2 為例，不剔除為 43.38 萬／坪（n=183），剔除後為
**47.32 萬／坪（n=38）**，差 3.94 萬（9%）。

`clean.py` 另擋來源端鍵入錯誤的未來交易日（實測 111S4～115S2 共 3 筆，
含一筆民國 122 年）。

### 2. 特殊交易剔除

依 115S2 台中市備註分布歸納黑名單，見 `clean.py::SPECIAL_REMARKS`：
親友／員工／共有人等特殊關係、政府機關標讓售、協議價購、僅車位交易、
毛胚屋、公共設施保留地、畸零地、未辦繼承標售、權利讓渡、換約、抵債、瑕疵等。

### 3. 尾端資料完整度

最近數期樣本仍在累積（實測 115/07 全台僅 227 筆、115/08 為 0 筆，
正常月份約 1,700 筆）。若照原樣輸出，圖表尾端會出現純屬資料缺漏的假性崩跌。

以「全台全屋齡樣本數 ÷ 前 N 期樣本數中位數」為覆蓋率，
**只檢查尾端連續不足的期別**（避免誤判農曆年等真實淡季，如 115/02 n=1,133）：

- 覆蓋率 < 0.35 → 該期完全不輸出（記於 `meta.dropped_periods`）
- 覆蓋率 < 0.85 → 輸出但標記未定案（記於 `meta.provisional_months`）

### 4. 低樣本標記（而非隱藏）

樣本數 `0 < n < MIN_N`（預設 3）時**仍輸出中位數**，另以 `low` / `roll_low` 標記：
單筆成交的「中位數」就是那一筆本身、統計代表性有限，但它是真實成交價，不予隱藏。
前端以虛線線段＋空心放大點呈現，表格加琥珀底色與 ⚠，卡片轉琥珀色並在
現值或基準值任一為低樣本時降級提示。

只有 `n = 0`（該期完全無成交）才輸出 `null`，圖上呈現斷點，不做內插推估。

## 分區範圍

實價登錄成屋檔**沒有社區名稱或里別欄位**（只有預售屋 B 檔才有「建案名稱」），
僅有門牌字串，因此商圈只能以路街白名單界定。定義見 `scripts/zones.py`：

| 分區 | 範圍 |
|---|---|
| 烏日全區 | 鄉鎮市區 = 烏日區，不做門牌篩選 |
| 高鐵特區 | 高鐵東路、高鐵路一～三段、高鐵一～七路、三榮路一～三段、三榮北路、三榮三／五／十六／十八路、榮泰街、榮泉街、站區路 |
| 明道商圈 | 中山路一段、興祥街、信義街、僑仁街、光德路、學田路、三民街、光日路、仁德街、文明街 |

高鐵特區與明道商圈刻意不重疊；未落入任一白名單者僅計入烏日全區。

## 已知限制

- **明道商圈幾無新成屋供給**：清洗後 115S2 全季 0 筆新成屋，全屋齡僅 11 筆
  （屋齡 8～32 年）。該區「新成屋」基準下多數期別樣本不足屬正常現象，
  跨區比較請改用「全屋齡」基準才有可比性。
- 單一社區（如明道國際花園城，僑仁街 31 號、96 年完工）成交量過低，
  無法支撐任何頻率的序列，故本專案以商圈為最小地理單位。
- **全台灣序列為 22 縣市合併中位數**，各期縣市組成變動會影響數值，
  僅作背景基準線參考，不等同官方住宅價格指數。
- 登記日 115/6/11～6/20 這 10 天目前兩種檔案皆未涵蓋（115S2 只到 6/10，
  現存最舊旬檔為 20260701）。115S3 季檔發布後，以
  `workflow_dispatch` 勾選 backfill 重跑即可補齊。
- 本專案輸出為自動彙整之統計結果，非不動產估價報告。
